Chapter 1. Executive System Architecture

Vidudhi is an intelligent hostel and residential campus management platform. It replaces outdated paper logbooks and fragmented spreadsheets with a single, synchronized digital environment. Whether a student is checking in for attendance, requesting emergency medical aid, booking laundry slots, or obtaining gate clearance, the system coordinates every action across mobile and desktop devices.

1.1 The 3-Tier Distributed Architecture

The platform is architected into three distinct layers to ensure speed, security, and scalability:

Layer Technologies Used Role & Human Explanation
Frontend Layer (Client SPA) React 18, Vite 5, Redux Toolkit, React Router 6, Lucide Icons, Vanilla CSS Design Tokens. The interactive portal loaded in the user's browser. It provides instantaneous page navigation without page reloads, role-specific navigation menus, fluid responsive layouts on mobile phones, and client-side biometric matching.
Backend API Layer (Server) Node.js 18+, Express.js 4, Helmet Security, CORS, Express-Rate-Limit, Morgan Logger. The central brain running in the cloud. It validates user requests, verifies digital signatures, calculates geofence distances, protects endpoints against password guessing (15 attempts/15 min limit), and serves REST API endpoints.
Database Layer (Persistence) MongoDB Atlas Cloud (Cluster: keerthana), Mongoose 8 Object Data Modeling (ODM). Enterprise cloud database cluster storing structured collections: Users, Rooms, Attendance Records, Complaints, Leave Passes, Visitors, Mess Menus, and System Audit Logs.

1.2 How the Frontend and Backend Talk to Each Other

Communication between the frontend and backend follows a strict, industry-standard REST API pattern:

  1. 1. Secure Handshake (Login): When a user logs in with their roll number or email and password, the frontend transmits an encrypted payload to POST /api/auth/login.
  2. 2. Digital Passport (JWT Token): The backend verifies the password using salted bcryptjs hashes. If valid, it returns a cryptographically signed JSON Web Token (JWT) containing the user's ID, role, and clearance level.
  3. 3. Authenticated Requests: For all subsequent requests, the frontend automatically attaches this token inside the HTTP header: Authorization: Bearer <JWT_TOKEN>.
  4. 4. Gatekeeping Middleware: Before executing any database read or write, backend middleware intercepts the request, verifies the signature, confirms user permissions (e.g. preventing a student from accessing admin controls), and only then executes the database query.

Chapter 2. Comprehensive Module Breakdown

Below is a humanized, detailed breakdown of all 20 modules that power the Vidudhi ecosystem.

1. Authentication & Role-Based Access Control
Security & Access
In Simple Words This is the digital gatekeeper of the hostel. Instead of having confusing login screens with leaked test accounts, the login page is clean, elegant, and simple. It supports 5 distinct hostel roles: Student Resident, Chief Warden, System Admin, Mess Manager, and Campus Doctor.

Backend API & Database POST /api/auth/login, POST /api/auth/google, GET /api/auth/me.
Backed by Mongoose User collection with bcryptjs salted passwords and brute-force rate limiter (15 requests/15 min).
2. Campus Overview & Command Center
Analytics
In Simple Words The first screen users see after logging in. For students, it highlights their room number, night roll-call status, outpass approvals, and dinner menu. For the Warden and Admin, it transforms into an executive telemetry cockpit tracking total residents, occupied beds, pending repairs, and active curfew clearances.
Frontend Tech & UX Real-time stat widgets, SVG Donut occupancy graphs, quick navigation shortcuts, responsive CSS grid.
Backend API & Database GET /api/admin/overview, GET /api/user/recently-accessed.
Aggregates database totals across Room, Complaint, Attendance, and Leave collections.
3. Smart Attendance Desk (GPS Geofencing + Biometrics)
Biometrics & AI
In Simple Words Traditional night roll-call requires wardens to walk door-to-door with paper registers between 8:00 PM and 9:30 PM. Vidudhi automates this completely. Students verify attendance on their own phone using two tamper-proof checks: First, GPS confirms they are physically inside the hostel boundary (≤ 300 meters). Second, their camera verifies their face using an AI neural network or their phone's fingerprint sensor.
Frontend Tech & UX HTML5 Geolocation API with Haversine distance formula; @vladmandic/face-api (128-dimensional ResNet-34 neural embedding inference with calibrated < 0.48 Euclidean distance); WebAuthn hardware biometric sensor API.
Backend API & Database POST /api/attendance/check-in, GET /api/attendance/daily, PATCH /api/attendance/override/:id.
Records GPS coordinates, face match distance, verification method, and timestamp in Attendance collection.
4. Room Allocation & Capacity Hub
Facilities
In Simple Words Keeps track of every single room and bed across Block A and Block B. Shows exactly which beds are occupied, which are vacant, room maintenance status, and roommates. Wardens can reassign beds with a click, while students can see their room details and roommates.
Frontend Tech & UX Visual room grid cards, bed allocation slot badges (Bed 1, 2, 3), occupancy filters (Fully Occupied, Partially Filled, Vacant).
Backend API & Database GET /api/rooms, GET /api/rooms/:id, PATCH /api/rooms/allocate.
Backed by Room schema with bed slots, resident roll number relations, and capacity counters.

Backend API & Database GET /api/complaints, POST /api/complaints, PATCH /api/complaints/:id/status.
